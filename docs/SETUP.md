# TutorPlace: локальный запуск и настройка MVP

TutorPlace работает как приложение Next.js на Node.js с локальной SQLite базой. Рабочие процессы приложения не используют Cloudflare Workers или D1.

## Запуск

Нужен Node.js 22.13 или новее.

```sh
npm install
npm run db:migrate:sqlite
npm run dev
```

Откройте `http://localhost:3000`. База по умолчанию находится в `.data/tutorplace.sqlite`; для другого расположения задайте `DATABASE_PATH`.

Задайте `ADMIN_LOGIN` и `ADMIN_PASSWORD` перед первым входом. Первый вход создаст аккаунт администратора платформы. Скопируйте `env.local.example` в `.env.local` и настройте значения, необходимые локальным сервисам и загрузке файлов.

## Аккаунты и каталог

- Репетитор может подать анкету через ссылку «Я репетитор» на главной странице.
- Новая анкета становится доступна после публикации администратором в разделе «Администрирование».
- Администратор может создать репетитора или отдельную учётную запись поддержки.
- Студент может иметь отношения с несколькими репетиторами; список учеников и уроков репетитор видит только в рамках своего кабинета.
- Старые аккаунты преподавателя и ученика сохраняются миграцией. Первому прежнему преподавателю присваивается роль администратора платформы, а существующие уроки связываются с ним.

## Расписание и бронирование

Доступность и бронирования хранятся отдельно для каждого репетитора. Google Calendar остаётся необязательной интеграцией: без неё свободные окна рассчитываются по расписанию TutorPlace и занятости в локальной базе.

Онлайн-оплата в MVP — симулятор. Кнопка подтверждает запись платежа и условную выплату репетитору в SQLite, но не списывает деньги и не связывается с платёжным провайдером.

## Видеовстреча и доска

Веб-интерфейс урока включает Jitsi Meet и Whitebophir под оболочкой TutorPlace. Секреты подписи остаются только на сервере.

Для Whitebophir:

```sh
cp env.local.example .env.local
```

Сгенерируйте секрет `openssl rand -hex 32` и задайте его как `WHITEBOPHIR_AUTH_SECRET` в `.env.local`. Запустите доску:

```sh
docker compose -f compose.local.yml --env-file .env.local up -d whitebophir
```

Сервис доступен приложению по `WHITEBOPHIR_URL`, по умолчанию `http://localhost:5001`.

Для видеовстречи используйте [официальный Docker Compose Jitsi Meet](https://github.com/jitsi/docker-jitsi-meet). Укажите `JITSI_DOMAIN`, `JITSI_APP_ID` и `JITSI_APP_SECRET` в `.env.local`, используя те же параметры приложения в конфигурации Jitsi. Локальный адрес по умолчанию в примере — `localhost:8000`. Отключите запись встреч в настройках Jitsi.

Инструкция по лицензии Whitebophir, хранению досок и доступу к медиапортам приведена в [LOCAL-LESSON-SERVICES.md](LOCAL-LESSON-SERVICES.md).

## Хранение файлов

Задайте `ASSIGNMENT_IMAGE_DIRECTORY` для хранения изображений заданий в локальной файловой системе. Для резервных копий используйте `DATABASE_PATH` вместе с папкой изображений. Новые изображения хранятся только на локальной файловой системе. Старые объекты из Cloudflare R2 требуют отдельного экспорта и копирования в каталог файлов до выключения прежнего хранилища.

## Перенос старой базы

Если у вас есть SQL экспорт прежней базы, сохраните его локально и импортируйте только в пустой файл:

```sh
D1_EXPORT=/path/to/export.sql npm run import:legacy-sql
npm run db:migrate:sqlite
```

Экспорт используется только как входной файл миграции. Запросы приложения после импорта идут к локальной SQLite базе.
